# Before public release and competition submission

The local prototype can be used without signing in. No account is required for the completed local development, data audit, core tests or demonstration workflow.

## Participant decisions and external steps

1. **Confirm eligibility.** The captured Devpost page has conflicting eligibility labels and body text. Confirm the participant's student/team status with the organizer if necessary. No inquiry has been sent on the user's behalf.
2. **Confirm data publication permission.** OneAquaHealth snapshot access was public, but its redistribution licence has not been verified. Keep the data private until permission is clear. Code can be published independently with data excluded; that alone does not create a working public demo.
3. **Review project claims and attribution.** The generated source and English description should be reviewed by the participant. Accurately disclose assistance where required. Eight calibrated weather tasks and retrospective evaluations are included. Do not describe them as contamination prediction, prospective validation or field results, and do not claim human-only authorship.
4. **Create the public code repository.** GitHub login may be needed here. Use the browser's normal sign-in flow; do not send passwords in chat. Select an appropriate licence for the original application code and keep third-party data licensing separate.
5. **Deploy a permitted demo.** A static host can serve the app. Hosting may need a GitHub/hosting account. Use approved data or another explicitly permitted loading arrangement. Do not publish extracted service credentials.
6. **Record the 3–5 minute video.** Follow DEMO_SCRIPT.md and upload through the participant's chosen video account. The provided script is ready, but no video has been recorded or uploaded.
7. **Submit on Devpost.** Devpost login, team details and the final repository/demo/video links are needed. The local prototype has not been entered in the competition.
